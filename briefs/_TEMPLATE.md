## 1. Question

One or two sentences. What decision will this answer help make?

## 2. Why it matters

Who has this problem (studios, solo devs, my own projects)? Why now?

## 3. Hypothesis

What I expect to find, before building anything. Being wrong here is fine and worth reporting.

## 4. Setup

- Project / map used, engine version, plugins and their versions
- Hardware (only if it affects the result)
- What exactly was built or tested, in a few bullets
- What was deliberately left out of scope

## 5. Method and metrics

How the result is measured. Prefer simple, honest metrics:

- time to a working result (hours, given as a range if uncertain)
- number of human interventions or corrections
- number of defects found after "done"
- frame time / memory, only when performance is the question
- lines of code or number of graph nodes, only when maintainability is the question

## 6. Result

What happened, with the numbers. Screenshots or GIFs from `media/`.

## 7. What worked / what did not

Two short lists. Include surprises and failure modes.

## 8. Verdict and recommendation

My engineering opinion, stated clearly: what I recommend, for whom, and under which conditions. Possible outcomes: adopt, adopt with conditions, build into BertaDevKit, buy, keep as project-local, park. The opinion must follow from the evidence above, and say how confident it is.

## 9. Limits

What this experiment does **not** prove. Sample size, engine preview builds, single machine, etc.

## 10. Reusable output

What I keep using after this brief (tool, template, prompt spec, checklist), and where it lives.

## 11. Applying it at work

How this changes the way I prototype on real projects: what I will now delegate, check, reuse or avoid. Keep it generic (no client details).

## 12. Next question

The follow-up question this result raises, if any.

---

### Video script (60–90 s)

1. **Hook (0–10 s):** the question, on screen, with the end result already visible.
2. **Setup (10–25 s):** what was tested, in one sentence.
3. **Demo (25–70 s):** the thing working, with the key number overlaid.
4. **Verdict (70–90 s):** the decision and one limit.
