## 1. Question

To sequence an interactive experience across several plugins, which approach is fastest to build and easiest to change when requirements change: StateTree, Logic Driver Pro, or a graph generated by an agent from a written spec?

## 2. Why it matters

Prototypes that combine several systems tend to end up with a giant "manager" Blueprint. Choosing the orchestration layer early saves time on every later prototype. The hypothesis behind it is documented in `lab/lab-architecture.md`.

For me: it closes the open Logic Driver question in my toolkit, and the slice is the vertical slice of the Sanctuary prototype (`lab/projects/biblical-sanctuary-prototype.md`).

## 3. Hypothesis

- StateTree is enough for a linear flow.
- Logic Driver pays off when the flow is reordered, branched or reused.
- Agents generate a first graph quickly but need corrections on plugin-specific nodes.

## 4. Setup

The same flow, built three times, using systems already validated in the Sandbox:

```text
Explore → Interact (Nice Interaction) → Inspect / Dialogue (Narrative Tales)
        → Atmosphere change (Ultra Dynamic Sky + Chameleon) → Reconstruct element → Next phase
```

1. StateTree (+ State Tree Tools).
2. Logic Driver Pro (requires purchase; decision rule in `toolkit/plugin-inventory.md`).
3. Agent-generated version from a written spec, in whichever of the two tools the agent handles better.

## 5. Method and metrics

- Build time for each version (range).
- **Change test:** after each version works, apply the same change request (reorder two phases and add one branch) and measure the time to apply it.
- Node / state count and how many custom glue functions each version needed.

## 8. Verdict and recommendation

Adopt Logic Driver as the orchestration layer, keep StateTree as the default, or use each for a defined kind of flow.

## 9. Limits

One flow, one developer who already knows the plugins. Learning time for Logic Driver is part of the cost and should be reported separately.

## 10. Reusable output

- The vertical slice (reused by the Sanctuary prototype)
- Reusable orchestration nodes or tasks, only if they appear in more than one version

## 11. Applying it at work

Choose the orchestration layer at the start of multi-system prototypes instead of growing a manager Blueprint.
